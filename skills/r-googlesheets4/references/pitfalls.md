# Pitfalls — the canonical errata table

Every trap that has burned a build, with the fix. Cross-reference rows
to deeper treatment in topic refs.

| Pitfall | Fix |
|---|---|
| Colors are hex | NO — Sheets uses `list(red=0-1, green=0-1, blue=0-1)`. Use `hex_to_color()`. |
| Indices are 1-based | NO — grid coordinates are **0-based** with exclusive upper bound. Always use `grid_range()`. |
| `reformat = TRUE` preserves formatting | NO — it **clears** existing formatting. Use `reformat = FALSE` when updating values in pre-styled sheets. See [writing.md](writing.md). |
| `[Red]` in number format | Not supported. Use `fmt_cond_negative()` for red-text-on-negative, or Sheets-specific `[Color53]`. See [number-formats.md](number-formats.md). |
| Formula locale | Sheets always uses commas as argument separator regardless of locale. Excel-EU's `;` is wrong. |
| Auth token expired / revoked, or "No saved Google login" from `gs_connect()` | Run once: `bash scripts/gs_setup.sh auth <email>` (opens the Google sign-in page; see [auth.md](auth.md)). For unattended cron, set `GS_SA_JSON` to a service-account key. |
| Rate limit (429) | `request_make()` retries automatically via gargle. Batch into one `batch_format()` call. Add `Sys.sleep(3)` between iterations. See [rate-limits-and-batching.md](rate-limits-and-batching.md). |
| 10M cell limit | One spreadsheet ≤ 10M cells. Split across spreadsheets if needed. |
| Sheet name with spaces in formulas | Use single quotes: `'P&L Summary'!A1:A10`. |
| `sheet_write()` overwrites everything | Use `range_write()` for targeted updates, `sheet_append()` for adding rows. |
| `fields` parameter in `repeatCell` | Must list ALL format properties being set. Missing a field = that property gets ignored, not cleared. The `fmt_cells()` helper computes this for you, one mask per property (see the `fmt_cells()` masks row below). |
| Merged cells + formatting | Format the FULL merged range, not just the top-left cell. |
| Double `=` in compound formulas | `glue("={f_a()}+{f_b()}")` produces `==SUMIFS(...)+==SUMIFS(...)`. Use `fraw()` to strip the leading `=` from inner builders. See [formulas.md](formulas.md). |
| `%||%` doesn't handle NA | `%||%` is NULL coalescing only. After `group_by/summarise`, use `mutate(across(where(is.character), ~ replace_na(.x, "")))`. |
| Nested `glue()` calls | Work but watch for escaped quotes. Prefer the `{fraw(f_...())}` pattern. |
| `fmt_group_cols()` returns 2 requests | Unlike other `fmt_*` helpers (1 request), `fmt_group_cols()` returns a 2-element list. Use `c()` not `list()` to flatten — otherwise `batchUpdate` fails silently. Same for `fmt_group_rows()`. See [formatting-batchupdate.md](formatting-batchupdate.md). |
| SUMIFS on filtered raw-data tabs | In per-dept workbooks, raw-data tabs contain only that dept's rows. Company-wide totals must be hardcoded — a SUMIFS on the filtered tab gives dept-only total. |
| Border column range off-by-one | `grid_range()` uses exclusive `endIndex`. Columns C:I (3-9) need `end_col = 9`. Verify borders visually. |
| Freeze ↔ merge conflict (BOTH directions) | Two symmetric HTTP 400s, same root cause — a merge and a frozen-column boundary cannot cross: (1) merging a range that spans a frozen col → "can't merge frozen and non-frozen columns"; (2) freezing a col that splits an existing merge → "can't freeze columns which contain only part of a merged cell". **The order doesn't save you** — whichever op runs second fails (and on a recreated tab, a late `fmt_freeze` after the merge registry runs is the classic trip). **Fix:** a full-width `A:*` banner merge requires `frozenColumnCount = 0` (freeze ROWS only); or start the merge after the frozen cols (`B1:Y1` not `A1:Y1`); or skip the merge entirely and paint the equivalent bg color + outer borders across the block via `repeatCell`+`updateBorders`, text in the leftmost cell with `wrapStrategy = "OVERFLOW_CELL"` — visually identical to a banner merge, no freeze conflict. Because one bad request fails the whole atomic batch, apply merges **per-tab** to isolate. |
| `batch_format()` silent failures | `request_make()` does NOT throw on HTTP 400 — it silently returns the error response; the wrapper only `message()`s the status (which scrolls off / hides behind `grep\|tail`). **A `tryCatch` around `batch_format()` will NOT catch a 400** (nothing is thrown), so a self-reported "N/N applied" can be false while 0 actually applied. The batchUpdate is **atomic** — one bad request fails ALL. **Fix:** pass `strict = TRUE` (added — stops on HTTP ≥ 400), or **re-read the live state** to verify; never trust the log line alone. |
| Timing: `flush_writes()` → `batch_format()` | Add `Sys.sleep(3)` between them on large sheets. Without it, Google may not have committed cell values before formatting arrives. |
| `request_generate()` says endpoint not recognized | `googledrive` exports a same-named `request_generate()` that doesn't know Sheets endpoints. Loading order issue. **Fix:** `gs_helpers.R` pins both functions explicitly. See [auth.md](auth.md). |
| Empty `list()` in `updateCells` collapses columns | `jsonlite::toJSON(list())` serializes to `[]` (array), not `{}` (object). Sheets drops `[]` placeholders and shifts cells one col left per skipped slot. **Fix:** use `structure(list(), names = character(0))` as the placeholder. |
| `OVERFLOW_OR_ELLIPSIS` is not a valid WrapStrategy | Returns HTTP 400. Valid values: `OVERFLOW_CELL`, `CLIP`, `WRAP`, `LEGACY_WRAP`. The `wrap` parameter in `fmt_cells()` maps `wrap=TRUE` to `WRAP`, `wrap=FALSE` to `OVERFLOW_CELL`. |
| `addConditionalFormatRule` stacks on re-runs | Each `batchUpdate` appends. Re-running 5× = 5 copies. **Fix:** use `fmt_delete_cond_rules()` first (reads actual count via `spreadsheets.get`). Never blind-delete a fixed range — fails HTTP 400 on missing index, taking down the atomic batch. Delete descending. See [conditional-formatting.md](conditional-formatting.md). |
| Row-inserting scripts double-insert on re-run | If your script does `insertDimension` at the top of a tab, re-running shifts everything down AGAIN. **Fix:** use a sentinel check — write an unambiguous string in cell A1 post-insert; before inserting, read A1 and skip if it matches. |
| Idempotent migrations: check destination, not FIRST_RUN | If a format batch partially fails, prior "first-run only" migrations never run; on next re-run FIRST_RUN is `FALSE` so migration is skipped forever. **Fix:** gate migration logic on the current destination state, not a first-run flag. Self-heals after partial failures. |
| Later `updateBorders` requests silently win | A row-wide bottom border on row 7 wipes the DOUBLE top border on row 8 (same edge). Only visible in the final effective format. **Fix:** apply emphasis borders in a final reassertion batch, or order assembly so emphasis comes last (last-writer-wins within one batchUpdate). |
| Wrote content to a hidden column | `A1` returns the title string, but user sees an empty colored bar — `columnMetadata.hiddenByUser[A] = TRUE`, often inherited from `sheet_copy()`. **Fix:** before placing user-facing anchor content, call `first_visible_col()` and write there. See [qa-post-build.md](qa-post-build.md). |
| Source-tab row-1 collides with new exec band | `sheet_copy()` + `insertDimension(rows 0–6)` shifts source tab's row 1 down to row 8 — right where you'd put a spacer. **Fix:** after `insertDimension`, `range_read` rows 8–10. If non-empty, clear and restyle (white bg, small height). |
| `cutPaste` for moving a sub-block while keeping refs intact | When two sections are misaligned by one column, use `cutPaste`: it auto-rewrites every formula in the workbook that referenced the moved cells. **Pattern:** `list(cutPaste = list(source = grid_range(...), destination = list(sheetId, rowIndex, columnIndex), pasteType = "PASTE_NORMAL"))`. Run *after* `insertDimension` and *before* writing new formulas. |
| Date strings render in non-English locale | `format(Sys.Date(), "%B %d, %Y")` honors `LC_TIME`. On Spanish/French dev machine the subtitle ships as `"Prepared abril 24, 2030"`. **Fix:** use `safe_locale_date()` from `gs_qa.R`. Don't rely on `"en_US.UTF-8"` — not all macOS / Linux installs have it. |
| `POSIXct` datetimes silently shift on write | Datetime columns are converted to sheet serials in the **spreadsheet's** timeZone (a sheet property, often `Etc/GMT` by default) — if it differs from the R session's TZ, every timestamp shifts by the offset with no error, and a read-back into the same session round-trips cleanly so the shift is invisible. **Fix:** pin `gs4_create(..., timeZone = Sys.timezone())` (what `gs_open_or_create()` does by default; its `time_zone` argument overrides it), or write ISO strings + a DATE_TIME number format. See [writing.md](writing.md) § "Writing dates & datetimes". |
| Chart sources in hidden cols silently fail | Chart whose `sourceRange` lies in `hiddenByUser=TRUE` cols renders as the empty-state placeholder. `addChart` returns 200 OK; the rendered chart is empty. No error response. **Fix:** place chart-helper data in *visible* cols, far right past chart pixel extents. Run `audit_chart_sources(ss_id)` (every tab) after every batch; it catches most cases but not a partial series loss, because while columns are hidden Sheets returns fewer series than the chart holds, so also compare the series count you read back with what you built. See [charts.md](charts.md). |
| Chart anchor outside the grid is a 400 | `sheet_write()` trims a tab to its data, so a chart anchored below it fails with HTTP 400 `rowIndex[26] is after last row in grid[6]`. **Fix:** grow the grid first (`gs_open_or_create(rows =, cols =)` or an `updateSheetProperties` request), or anchor the chart on another tab with `anchor_sheet_id`. |
| A hand-built chart source needs the `sourceRange` wrapper | A domain or series is `list(sourceRange = list(sources = list(<grid range>)))`; a bare `sources` key is rejected with HTTP 400 (`Unknown name "sources"`), and `batch_format()` only logs a 400. The `fmt_chart_*` helpers build it for you. |
| `BasicChartSeries` has no `name` field | Multi-series charts legend as "Series 1, 2, …" by default. Legend label comes from the **first cell of `sourceRange`** when chart spec `headerCount >= 1`. **Fix:** write a label cell into the col immediately left of each series; source range starts at that label col; pass `header_count = 1L`. |
| BAR series must target `BOTTOM_AXIS` | "Bar charts series may only target the BOTTOM_AXIS" HTTP 400. Default `LEFT_AXIS` works for LINE/COLUMN but breaks BAR. **Fix:** pass `axis = "BOTTOM_AXIS"` on each series. `fmt_chart_bar()` handles this. |
| `waterfallChart.connectorLineStyle.colorStyle` is invalid | HTTP 400 — `LineStyle` only has `width` and `type`. **Fix:** drop `colorStyle`. Color the bars via `series.positive/negative/subtotalColumnsStyle`. |
| Per-scenario chart sets risk silent same-data bugs | Off-by-one in scenario offset map → all charts read the same row. **Fix:** post-build, read back helper-block source cells for at least two scenarios and assert values *differ*. `stopifnot(read_helper(bull_top, "Closing") != read_helper(bear_top, "Closing"))`. |
| Sign-already-negative source rows cause double-negation | Financial-statement views often pre-sign expense rows. Writing `-PNL!Y19` on a row that already returns `-100,000` double-negates → positive. **Fix:** before writing `-X!Ynn`, read 2 cells of the source. See [finance-models.md](finance-models.md) §5. |
| Non-contiguous month col ranges break SUM/MIN/MATCH | Inserting a "Year Total" col between Dec (P) and the next January (now R) makes the 24-month layout `c(5:16, 18:29)`. `SUM(E:AC)` double-counts the Year Total cell. **Fix:** use range helpers — `SUM(E:P, R:AC)` for non-contiguous; `MIN(E:P, R:AC)`; nest two MATCHes with IFERROR fallback. |
| Two-tab models with cross-tab refs need ordered creation | Tab A's formulas referencing `'Tab B'!<cell>` need Tab B to exist first or `#REF!`. **Fix:** create both tabs early; populate referenced tab first; then populate referring tab. See [finance-models.md](finance-models.md) §8. |
| Merged-cell color readback is misleading | When you read `effectiveFormat.backgroundColorStyle` on a cell INSIDE a merge (not the top-left "merge head"), the API returns the underlying cell's pre-merge color (often white) — **not** the merge head's color that the user actually sees. A readback showing D40=`#FFFFFF` when B40:H40 is merged into one cell with a dark fill is normal; the displayed visual is navy. **Fix:** before reading colors to verify visual state, fetch `sheets[].merges` from `spreadsheets.get(include_grid=TRUE)` and read only the merge head, OR verify by writing a `repeatCell` to the head cell and trust the displayed result. |
| `HYPERLINK("#gid=X&range=Y", …)` URLs are literal strings — they don't auto-shift on row delete | `=HYPERLINK("#gid=" & 123456789 & "&range=B128", "Section 1")` survives row insertions/deletions WITHOUT updating its `range=` parameter — Sheets does not parse the URL string. After deleting 100 rows above row 128, the literal `B128` now points to a far-below cell. **Fix:** after any structural row-shift on a tab that contains target rows of HYPERLINK URLs, re-write the hyperlinks explicitly with corrected `range=` arguments. Compute new row = old row − (rows deleted above it). Audit pattern: grep formula text for `range=B<N>` and verify each target row still holds its intended anchor content. |
| `updateCells` clear pattern: `fields="userEnteredValue"` with NO `rows` payload | To CLEAR a cell range's value/formula via `batchUpdate.updateCells`, send `{range, fields: "userEnteredValue"}` with **no** `rows` field. Sending `rows: [{values: [{}]}]` is treated as a no-op (update to empty object = update to nothing) — the cell keeps its existing content. Confirmed live: a large batch with `rows: [{values: [{}]}]` reported success but left target cells unchanged, causing a downstream double-count bug. **Fix:** for explicit clears, omit `rows` entirely from the request body. The fields mask alone tells Sheets "reset this property." |
| `range_read(range=...)` row-index mapping can be off-by-one vs sheet rows | `googlesheets4::range_read(range = "B127:B400", col_names = FALSE)` returns a tibble. Mapping `g$row <- 127:(127 + nrow(g) - 1)` looks correct but can be off by one in some versions/edge cases — particularly when the returned data starts at a different row than the range's `startIndex` (e.g., trailing empties trimmed). **Fix:** when the row-index matters (e.g., locating banner rows for downstream writes), verify by reading 3-5 adjacent rows around the suspected hit and matching the actual displayed content; or query via REST `spreadsheets.get` with explicit `gridRange` and use the returned indices directly. Off-by-one in this map will land subsequent format/write ops 1 row above or below the intended target. |
| `setDataValidation` always renders as Arrow, never Chip | The Sheets API v4 `DataValidationRule` does not have a display-style field (no `displayStyle`, no `dropdownStyle`, no `dropdownDisplay`). `showCustomUi=TRUE` is **not** a chip switch — it just enables the caret-dropdown UI. `fmt_dropdown()` / `fmt_dropdown_range()` therefore always produce **Arrow** display. The "Multiple values" toggle in the UI only appears on Chip-style dropdowns, so this also blocks multi-chip selection. Open feature request: [googleapis/google-api-python-client#2676](https://github.com/googleapis/google-api-python-client/issues/2676) (Oct 2025, no resolution). **Fix:** wrap the range in a Sheets Table (`addTable` + `updateTable` with `columnType: "DROPDOWN"`). See [data-validation.md](data-validation.md) § "Chip vs Arrow" and [modern-features.md](modern-features.md) § "Sheets Tables & chip-style dropdowns" for the pattern. |
| `addTable` with `columnProperties.columnType="DROPDOWN"` in one request → HTTP 500 INTERNAL | Submitting `columnProperties` inside the initial `addTable` request, with any column typed as `DROPDOWN`, reliably returns `{"code":500,"status":"INTERNAL"}`. A plain `addTable` (no column properties) succeeds. **Fix:** two-step pattern — `addTable` plain to create the table and capture the assigned `tableId`, then `updateTable` with `fields="columnProperties,rowsProperties"` to set the DROPDOWN columns. Other column types (e.g., `TEXT`, `CHECKBOX`) may also be affected; default to the two-step pattern. |
| `columnIndex` in `columnProperties` is sheet-absolute → HTTP 400 | Inside `addTable` / `updateTable`, `columnProperties[].columnIndex` is **relative to the table's range**, not the sheet's columns. A table starting at sheet col D with 4 columns expects `columnIndex` values 0, 1, 2, 3 — not 3, 4, 5, 6. Error: `Column index must be between 0 (inclusive) and the number of columns (exclusive) in the table.` **Fix:** index your column-properties relative to `range.startColumnIndex`, not the sheet origin. |
| addTable on a range that already has banding → HTTP 400 | `You cannot add alternating background colors to a range that already has alternating background colors.` Sheets Tables include their own banding layer; you can't stack them. **Fix:** for idempotent re-runs, look up the existing table by name and `deleteTable` it first; for freestanding pre-existing banding, send a `deleteBanding` request before `addTable`. |
| Pre-existing per-cell `dataValidation` shadows Table column dropdown | After `addTable` with `columnType: "DROPDOWN"`, if the cells already carried a per-cell `dataValidation` rule from a previous `setDataValidation`, behavior diverges — readers see both the table-column dropdown and stale per-cell validation; chip rendering is degraded. **Fix:** before `addTable`, clear per-cell validation via `updateCells` with `fields = "dataValidation"` (no `rows` payload — see the existing pitfall on this clear pattern). |
| "Allow multiple values" toggle is UI-only — not API-controllable | Even after you've achieved chip-style rendering via Tables `columnType: "DROPDOWN"`, the "Allow multiple values" toggle (right-click → Data validation → checkbox) is a **separate setting** and is NOT exposed by REST `DataValidationRule`, Tables `columnProperties.dataValidationRule`, or Apps Script `DataValidationBuilder` (no `setMultipleValuesEnabled()` method). Without it ON, the chip dropdown still acts as single-select-replace-cell, defeating most of the chip UI's value. Tracking: [googleapis/google-api-python-client#2676](https://github.com/googleapis/google-api-python-client/issues/2676) (open as of Oct 2025). **Fix:** ship every chip-dropdown build with an in-sheet amber instruction banner adjacent to the dropdown range telling users to flip the toggle once per copy. See [data-validation.md](data-validation.md) § "Allow multiple values toggle". Re-check API release notes quarterly. |
| `INDEX(named_range, ROW_ARRAY)` doesn't spill in `ARRAYFORMULA` | A common pattern to populate N rows from a 1-col named range — `=ARRAYFORMULA(INDEX(my_range, ROW($A5:$A207)-4))` — silently returns only the FIRST cell value (a scalar), not the N-cell array. Sheets evaluates `INDEX` with array `row_num` as a scalar lookup, not iterating. **Fix:** either (a) write the N values as static cells via `updateCells.userEnteredValue`, or (b) use a spill-friendly construct like `=ARRAY_CONSTRAIN(my_range, 203, 1)` placed at the anchor cell. Static values are most robust when the source is stable. |
| A formula written without a leading `=` is stored as TEXT | A cell whose value is `'Sheet'!B11` (or `SUM(B2:B9)`) **without** a leading `=` is stored as a literal string — it displays the formula text and `SUM`/math silently exclude it (e.g. a total row reads low because the text cells count as 0). Bites when building cross-sheet refs with `sprintf`/`glue`. **Fix:** ensure the written value begins with `=`. Note `fraw()` deliberately *strips* `=` to concatenate inner builders — the FINAL written string must still start with `=`. Verify by reading back: the cell should return the evaluated number, not the formula text. |
| `read_sheet()` NA filter trap (`nzchar(NA)==TRUE`, `NA != x` ==NA) | Empty source cells read back as `NA`. A filter like `nzchar(cat) & cat != "#N/A"` lets `NA` rows THROUGH — `nzchar(NA)` is `TRUE` and `NA != "#N/A"` is `NA` — so the kept set contains `NA`, which then crashes downstream `if(...)` with "missing value where TRUE/FALSE needed", or silently corrupts a join/aggregate. **Fix:** put `!is.na(x)` FIRST in the predicate — R's `&` short-circuits `FALSE & NA → FALSE`, neutralizing the rest. Belt-and-suspenders: wrap scalar conditions in `isTRUE(...)`. |
| `read_sheet()` drops entirely-empty LEADING/TRAILING columns | An all-blank first or last column in the requested range can be trimmed from the returned tibble, shifting every positional index (`df[[7]]` is no longer source col G). **Fix:** when column position matters, read with an explicit A1 range and assert `ncol()`/expected names, or use the REST `spreadsheets.values.get` with `majorDimension="ROWS"` and read by absolute column. (Related: empty-`list()` collapse row above, and the `range_read` off-by-one row below.) |
| Parsing numbers from formatted/text cells | Cells read back as text may carry `$`, thousands commas, `%`, or stray spaces. `as.numeric(gsub("[, ]", "", x))` returns `NA` on a leading `$`. **Fix:** strip everything except digits/dot/minus — `as.numeric(gsub("[^0-9.-]", "", x))` — exposed as `parse_num()` in `gs_qa.R`. Accounting parentheses `(100)` lose their sign under this; normalize `()`→leading-`-` first if your source uses them. |
| Idempotent merge re-apply after tab rebuild | A build that does `sheet_delete()` + `sheet_add()` (or otherwise recreates a tab) **wipes all manual merges**. Re-applying a declarative merge registry naively trips "already merged"/intersecting errors against merges the tab's own format step created. **Fix:** in ONE atomic batch per tab, `fmt_unmerge(range)` immediately followed by `fmt_merge(range)` for each registry entry — unmerge is a no-op when nothing's there, so the pass is idempotent. Keep the registry in the build and document a refresh step (re-probe live merges via `spreadsheets.get fields=sheets(properties(title),merges)`). |
| Per-cell read loops | Reading cells one API call at a time is orders of magnitude too slow and burns the read quota — long QA scripts built this way get killed. **Fix:** one batched range read per tab/block (`range_read` with explicit range, `range_speedread`, or `values.batchGet`). See [reading.md](reading.md). |
| Formatted reads silently corrupt numeric work | Reads return display strings (`"$1,234.56"`, `"(123)"`) — `as.numeric` fails, and a `col_types="c"` read can silently zero comma-formatted amounts in downstream sums. **Fix:** for reconciliation-grade numbers, read via REST with `valueRenderOption="UNFORMATTED_VALUE"` (+ `dateTimeRenderOption="SERIAL_NUMBER"`) so no string-parsing exists to get wrong. See [reading.md](reading.md) § Unformatted read. |
| Pre-encoding the `ranges=` query param | `utils::URLencode()` on a range passed via `params = list(ranges = ...)` double-encodes it (gargle/httr encodes query params) → "Unable to parse range" or empty matches. **Fix:** encode a range ONLY when it sits in the URL *path* (`values/{range}`); pass query params raw. See [api-endpoints.md](api-endpoints.md) § URL-encoding ranges. |
| Re-wrapping `gs4_token()` for httr calls | `gs4_token()` already IS an httr config object. Wrapping it in `httr::config()`/`add_headers()` breaks auth on raw endpoint calls. **Fix:** pass it directly: `httr::GET(url, gs4_token(), ...)`. |
| Drive export endpoint 429s under bursts | `export?format=pdf` rate-limits multi-tab bursts, and gargle's auto-429-retry does NOT apply (it only covers `request_make()` API calls). **Fix:** retry with backoff (the 5-try `Sys.sleep(15*i)` loop is built into `export_sheet_as_pdf()` in `gs_qa.R`) and, in your own multi-tab loop, sleep ~10s between tabs. |
| **API-written `=HYPERLINK()` links don't work on first click** | The formula evaluates (label shows, `effectiveValue` computes) but Sheets never generates the evaluated `hyperlink` (click-to-open chip) metadata for HYPERLINK formulas written via the values API — clicking does nothing until a human re-enters the cell (enter → space → enter re-parses it). Affects EVERY such cell, sheet-wide; easy to ship a whole workbook this way unnoticed. Diagnose: `spreadsheets.get` with `fields=...values(hyperlink,userEnteredValue)` — `hyperlink` is ABSENT while `formulaValue` is present. **A FORMULA-render regex check (`^=HYPERLINK\(`) passes and cannot detect this.** **Fix:** write link cells as rich text — label string + `textFormat.link.uri` via `updateCells` — using `link_cells_req()` in `gs_helpers.R` (migrate existing content strings with `parse_hyperlink()`). QA by asserting `userEnteredFormat.textFormat.link.uri` presence, not formula text. |
| `fmt_cells()` masks, layered styling and rich-text links | `fmt_cells()` sends one field mask PER property (`userEnteredFormat.textFormat.fontSize`, `.bold`, `.italic`, `.underline`, `.fontFamily`, `.foregroundColorStyle`, plus `backgroundColor`, `numberFormat`, alignment, wrap). A later call that sets only `font_size` therefore keeps the bold, colour and family set earlier on those cells, and it keeps a `textFormat.link`. **To reset a property, set it explicitly** (`bold = FALSE`): a property you leave out is never cleared. `apply_style()` goes through `fmt_cells()`, so it behaves the same. A hand-written `repeatCell` whose mask is `userEnteredFormat` or `userEnteredFormat.textFormat` still replaces the WHOLE object (and wipes links), so send such requests before the styling and link requests. |
| Partial unmerge of a differently-shaped old merge is a 400 | The same-shape `fmt_unmerge()`+`fmt_merge()` idempotency pattern breaks the moment a redesign CHANGES a row's merge shape (old build merged B:F, new spec merges B:E): unmerging the new shape partially overlaps the old merge → "You must select all cells in a merged range" → the whole atomic batch fails. `range_clear(reformat=TRUE)` does NOT remove merges either. **Fix:** unmerge the entire worked area once (`fmt_unmerge(sid, 1, 80, 1, 13)` — a range containing no merges is a no-op), then apply the new merge registry. |
| Pinned row heights clip variable wrapped text | `fmt_row_height()` pins are fine for structural rows but clip narrative/matrix rows whose wrapped text length varies per cell — every content tweak reopens the clipping whack-a-mole (caught repeatedly in PDF visual QA). **Fix:** pin only titles/headers/spacers; for content rows send `fmt_auto_resize_rows()` (autoResizeDimensions ROWS) LAST in the batch — it overrides earlier pins and fits final wraps. |
| `Could not resolve host: sheets.googleapis.com` while Drive calls work | Some networks' resolvers return IPv6-only (AAAA) answers for individual googleapis hosts; with no usable IPv6 route, curl reports a resolve failure for that ONE host while others (with cached A records) still work — looks like flaky DNS, is 100% reproducible per host. Diagnose: `dig +short host` resolves (bypasses system resolver) but `curl` fails; `dscacheutil -q host -a name <host>` shows only `ipv6_address` rows. **Fix:** force IPv4 process-wide before auth: `httr::set_config(httr::config(ipresolve = 1L))`. gargle/googledrive/googlesheets4 all route through httr, so one line covers everything. |
| USER_ENTERED swallows a leading apostrophe | A cell text starting with `'` (e.g. `'Quarterly bonus' as labeled…`) written via the values API with `USER_ENTERED` loses the apostrophe (it is the treat-as-text marker), and a leading `+` becomes a formula. **`write_cell()` and `write_block()` handle this:** text starting with `+ - @ '` gets one `'` prefix, which Sheets removes again, so the visible text is what you passed; `as_text = TRUE` keeps ID-like text (`"00123"`) as text. **Keep the guard only for hand-built `values.batchUpdate` values (`range_write()` sends typed values and is unaffected):** rephrase so the quote is not first, write via `updateCells` `stringValue` (no parsing), or `if (startsWith(v, "'")) stop(...)`. See [buffered-writes.md](buffered-writes.md). |
| `LET()` bindings evaluate in scalar context | A binding computed from a range, `=LET(a, A1:A3*2, SUM(a))`, silently keeps ONE element: Sheets applies implicit intersection and takes the element on the formula's own row (with `A1:A3` = 5, 15, 25 this returns `10` in row 1, not `90`; `=SUM(A1:A3*2)` in row 3 returns `50`). No error, just wrong sums. Passing the range alone and computing in the next binding (`LET(a, A1:A3, b, a*2, SUM(b))`) gives `#VALUE!`. **Fix:** wrap every computed array in `ARRAYFORMULA()` inside the binding: `=LET(a, ARRAYFORMULA(A1:A3*2), SUM(a))` returns `90`. Do the same for computed arrays inside `LAMBDA` bodies. Read a few results back to check; a wrong total looks plausible. |
| `(x-y)+(x<=y)` is not a safe zero-denominator guard | The trick makes the denominator 1 when `x<=y`, but it only works if `x-y` is never `-1`: `x-y = -1` gives `-1+1 = 0` and `#DIV/0!` (for example `1/((5-6)+(5<=6))`). **Fix:** `(x-y)*(x>y)+(x<=y)` is `x-y` when `x>y` and exactly `1` otherwise, for every input. |
| `link_cells_req()` keeps the text colour the cells already had | Only `textFormat.link` is written, so a link cell with no earlier colour renders plain black, not link blue. **Fix:** pre-colour the cells blue (and underline them) with `fmt_cells(font_color = ..., underline = TRUE)` in an earlier batch, then send the link requests; the link keeps that colour. |
| `values.update` and `values.get` take their range differently | `values.get` carries the range only in the URL path, so it MUST be encoded (`utils::URLencode(rng, reserved = TRUE)`; `read_values()` does it). Through `request_generate()`, `values.update` ALSO copies `range` into the request body, so an encoded range fails HTTP 400 `Request range[...] does not match value's range[%27...]`; a raw range with a space, quote or `&` (`'P&L Q1'!A1`) never leaves R (`curl: Malformed input to a URL function`). **Fix:** do not hand-build `values.update` for tabs like that: write through `values.batchUpdate` (`flush_writes()`; ranges go in the JSON body, nothing to encode) or `range_write()`. |
| `values.batchGet` with a vector of ranges fails in `request_generate()` | `params = list(ranges = c("A!A1:B2", "B!A1:B2"))` stops with `values must be length 1` (gargle's request builder takes scalar params only). **Fix:** `read_values(ss, c(range1, range2))` makes one `values.get` call per range, URL-encodes each, retries 429 and returns a named list of matrices. See [reading.md](reading.md). |
| A named list of requests is sent as a JSON object | `lapply(c(a = 1, b = 2), function(i) fmt_...)` keeps its names, and a named list serializes as an object: HTTP 400 `Unknown name "a" at 'requests'`. `batch_format()` now drops the names. A hand-built `request_generate("...batchUpdate", params = list(requests = ...))` does not: wrap it in `unname()`. |
| Re-running a build stacks objects or hits "already exists" | `addNamedRange`, `addBanding`, `addProtectedRange` (whole sheet), `addFilterView` and `addTable` answer HTTP 400 on a second run. `addChart`, `addSlicer`, `addConditionalFormatRule` and `addDimensionGroup` do NOT fail: they stack (two charts, doubled rules, group depth 2) and the sheet looks subtly wrong. A leftover freeze can also break the next banner merge (see the freeze/merge row above). **Fix:** call `gs_reset_tabs(ss, TABS)` (the tab names the script builds) right after `gs_open_or_create()` so every run starts clean. See [creating-and-tabs.md](creating-and-tabs.md). |
| A custom conditional-format formula cannot reference another tab | `=A1>NR_LIMIT` (named range on another tab) and `=A1>Data!$B$10` both fail HTTP 400 `Invalid ConditionValue.userEnteredValue`. **Fix:** echo the value into a same-tab cell and point the rule at it, or use `INDIRECT("Data!B10")`. See [conditional-formatting.md](conditional-formatting.md). |
| Deleting a named range turns its formulas into `#REF!` for good | `deleteNamedRange` rewrites every formula that uses the name, on any tab, to `#REF!` (`=NR_X*2` becomes `=#REF!*2`); adding the name back does NOT repair them. Bites rebuild scripts that delete and re-add names, and `gs_reset_tabs()` on a subset of tabs. **Fix:** rebuild together every tab whose formulas use the deleted names (`gs_reset_tabs(ss, googlesheets4::sheet_names(ss))` resets all) and rewrite their formulas afterwards; `keep_values = TRUE` therefore leaves named ranges alone. |
| Validation rules do not stop API writes | `setDataValidation` guards typing in the UI only. Values written through the API bypass it: a cell with `NUMBER_BETWEEN` 0 to 1 accepted `5` from `flush_writes()` (checked live; `write_block()` goes through `flush_writes()`). A script therefore cannot test that a rule rejects bad input, and a rule never proves the data is clean. **Fix:** check what a script wrote with `read_values()`; test rejection by hand in the UI. See [data-validation.md](data-validation.md). |
| `COUNTIFS(range, "*")` is not "count everyone" | The wildcard `*` matches text cells only. It skips numbers and truly empty cells, and it counts a formula that returns `""`. Checked live on `a`, `5`, empty, `d`, `7`, `=""`: `"*"` gave 3 and `"<>x"` gave 6. A head count over a column with blanks or numbers comes out low. **Fix:** `"<>x"` (anything that is not `x`) counts every cell, blanks included; `"<>"` counts non-empty cells (a formula's `""` too); `"?*"` counts text with at least one character. |
| Formulas that return `""` sort FIRST in a descending sort | `SORT(range, 1, FALSE)` over `3`, `1`, `2` and a cell holding `=IF(1=1,"","x")` returned `""`, 3, 2, 1; ascending puts the `""` last. A sort over a range pre-filled with guard rows (`=IF(A5="","",...)`) therefore buries the real rows under a block of blanks. Checked live with `SORT()`; the same order is reported from the showcase builds for a filter and a slicer. **Fix:** sort ascending, keep the guard rows out of the sorted range, or drop them first: `=SORT(FILTER(r, r<>""), 1, FALSE)` (checked: 3, 2, 1). |
| `f_safe_div()` returns `""`, so `ISNUMBER`-guarded consumers hide the worst case | `f_safe_div(spend, budget)` is `""` when the budget is 0 or blank. A status such as `IF(ISNUMBER(x), IF(x>1,"Over","OK"), "")`, a sparkline or an over-budget count then skips exactly the category that has spending and no budget at all. **Fix:** test the denominator where the ratio is the bad news and show a status: `=IF(C5<=0, IF(D5>0,"no budget",""), D5/C5)`, and count "no budget" as over budget in the roll-ups. |
| `range_clear()` resets formats by default | `googlesheets4::range_clear()` has `reformat = TRUE`: it removes number formats, fills and borders along with the values, so blanking the inputs before a test or a refill unformats them. **Fix:** `range_clear(..., reformat = FALSE)`, or `gs_clear_values(ss, "Inputs!B2:B20")` (one `values.clear` call; formats, validation and notes stay). |
| `write_block()` with a character matrix sends numbers as text | `rbind(c("Total", 1234.5, 0.25))`, `cbind(labels, nums)` and `matrix(c(...))` make every cell character, so `write_block()` sends `"0.25"` as a string and Sheets parses it as if typed. Checked live (decimal-point locale): the value arrives as a number, but a percent or date format already on the cell is dropped (PERCENT, DATE, DATE_TIME, and a NUMBER format with a `%` pattern: `0.25` shows as `0.25`, a date serial as `46053`), while CURRENCY and plain NUMBER formats (`$#,##0.00`, `#,##0.00`, `$#,##0;($#,##0);"-"`) were kept. Numbers written as typed values (a numeric matrix or a data.frame column) kept every format. Text is parsed like typing in other ways too: `"50%"` becomes 0.5 with a percent format, `"2026-01-31"` becomes a date, `"00123"` becomes 123, and `2e6` as text lands with a scientific format. **Fix:** write mixed rows from a data.frame (column types survive), or one `write_block()` per typed block; `as_text = TRUE` keeps ID-like text as text; re-apply the number formats after writing a character matrix. See [buffered-writes.md](buffered-writes.md). |
| AREA charts can drop the last x-axis label when narrow | A narrow AREA chart can leave off the label of its last category (reported from the showcase builds), so the final month looks missing. **Fix:** draw the series as COLUMN or COMBO, or widen the chart (`size = c(width, height)`). |
| Pivot-table labels render in italic | Sheets shows pivot row and column labels in italic (reported from the showcase builds), and `fmt_cells()` has one mask per property, so a layered call (bold, a fill) keeps that italic. **Fix:** pass `italic = FALSE` in the layered call. |
| PDF export repeats frozen rows on every page and has no print setup | By default the export repeats the frozen rows at the top of every page (checked: a frozen header row printed on all 6 pages of a 150-row tab). The Sheets API has no print settings (page breaks, margins, headers); the only knobs are the export URL's options, which `export_sheet_as_pdf(extra = )` appends as given (its default is `&portrait=false&size=A4&fitw=true&gridlines=false`). **Fix:** add `&fzr=false` to `extra`, keeping the other options (`extra` replaces the default string): the header then prints on page 1 only (checked, page images opened). Read the page splits that remain in `visual_qa()` as print layout, not as a defect of the sheet; whoever prints sets page breaks in File > Print. |
